# Analysis

## Scope

Initial project framing for a backend-first node harness platform. This analysis intentionally stays at the architecture and contract level.

## Current Direction

The system is centered on a generic harness that can wrap Linux processes, scripts, and later long-lived services. The graph engine is distinct from the execution runtime and from any frontend presentation layer.

## Design Constraints

- portable canonical types are required
- process boundaries are treated as untyped transport boundaries
- type validation occurs at declared port contracts
- lifecycle and trigger models are independent
- services and one-shot tasks must coexist

## Immediate Next Specs

1. Canonical type algebra
2. Harness SDK definition schema
3. Runtime lifecycle and state model
4. Command/query/event schema
