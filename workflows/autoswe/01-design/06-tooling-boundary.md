# Tooling Boundary Workflow

## Purpose

Define what belongs in portable workflows and what belongs in project-local tools.

## Workflow Owns

- design methodology
- stage sequencing rules
- artifact requirements
- review criteria
- escalation rules
- tool suggestion and tool request policy

## Tools Own

- project state storage
- dependency tracking
- progress tracking
- traceability
- search and indexing
- schema storage
- history
- project-specific queries

## Source Of Truth Rule

Workflows define how the system should reason and what it should produce.

Tools hold durable project state and enforce structured writes.
